对话

上下文条数 = 每次发给模型的最近消息数（系统提示词不计入）。输出上限与上下文窗口不在本页配置：它们按模型名统一维护在「模型元数据」表里，全站渠道共用一份，发送时按「窗口 − 预估输入」自动压缩输出、并裁剪过长的历史消息。温度留空则不发送该参数；推理型模型（如 o 系列、DeepSeek R1）可能不接受 temperature，被拒时会自动去参重试。

调用上游 AI 接口的最长等待时间。生成长文或使用较慢的模型/平台时适当调大。若上游根本连不上（地址错误、网络不通），会更快返回明确提示，不受此值影响。

填写后所有出站请求（含「模型元数据」拉取 litellm 价格表）都走该代理。支持 http://、https://、socks5h://。国内网络直连 raw.githubusercontent.com 常下到一半卡死，走代理可稳定完成。

模型元数据

一句话：这里是全站输出上限与上下文窗口的唯一入口。按模型名维护，所有渠道共用一份；供应商里不再单独配置，对话设置里也没有全局上限了。

⚠️ 推理模型（带思维链）必看：思维链和正文抢同一个额度。额度太小（如 8192）会被思维链吃光，导致正文空白、回答中途停止。给这类模型填 32000 或更高的输出上限；额度不够时系统会压缩思维预算保住正文。

🔍 有 0 个模型待人工复核：这些模型是加进渠道时自动补的兜底值，并非该模型的真实规格。请核对后点「确认」保留，或点「编辑」改成正确数值。

💰 关于计费：当前系统默认按调用次数扣费，不按输入/输出 token 计价。本表的价格仅作展示与估算参考，不参与实际扣费（渠道若单独设为「按 token」计费，用的是该渠道自己的单价，与本表无关）。因此请按次数在「模型」界面给各模型合理定价，即按单次调用的大致成本来折算。

展开看详细说明（新手向）

这个表是干什么的？它是每个模型的「能力档案」。你在这里登记某模型最多能听多少字、最多能说多少字、多少钱一万字，全站所有渠道共用一份。匹配只看模型名，跟你在哪个渠道调用无关。

三列分别是什么意思：

  • 输入窗口：模型一次能「听」多少（含聊天历史）。防止内容太长塞不进去；发送时按「窗口 − 预估输入」自动压缩输出。
  • 输出上限：模型一次最多能「说」多少，对应请求里的 max_tokens。这是模型的能力上限，不是每次都必须说这么多。
  • 价格 $/M：每百万 token 的单价，只用于展示和估算花费，不影响回答。— 表示该模型没有这项或不提供。

没匹配到本表的模型会怎样？把模型加进渠道时，如果表里还没有它，系统会自动补一条兜底值（输入窗口 131072、输出上限 8192；升级前若设过全局「单次输出上限」，则沿用那个值）并标注待复核，同时出现在本表里。你可以：

  • 点确认：认下这组数值，去掉待复核标记；
  • 点编辑：改成该模型的真实规格（推荐，兜底值通常偏保守）；
  • 点从 litellm 同步：多数常见模型能从公开价格表里直接取到真实值。

「待复核」是怎么来的？自动补的兜底值、以及从上游报错里自动学到的窗口，都会打上这个标记——它们是猜的，不是厂商规格。手工编辑或点确认后标记即消失。

来源三种标记：手工＝你自己填的，同步不会覆盖；同步＝来自 litellm 公开价格表；自动＝没匹配上时补的兜底值，需要复核。

数据从哪来？点「从 litellm 同步」从 litellm 的公开价格表批量拉取，覆盖 4000+ 模型。

为什么不显示「公司」？上游表里的 litellm_provider 指的是托管平台（如 bedrock、azure、openrouter），同一个模型常同时挂在多个平台下，并不是模型厂商，所以不展示。同一模型多个平台报价不一致时，本表按多数平台一致的值取用。

模型汇总

一句话：把多个渠道的模型合并成一个前台可见的 ID。开启后，被汇总的模型在前台和开放 API 里只显示这一个 ID，看上去就和「只添加了一个供应商、只有一个模型」完全一样；请求会按你选的策略在这些渠道之间分流。

「同名自动汇总」的成员是实时计算的：渠道新增或改名后自动跟上，不需要重新生成。你仍然可以单独改它的显示顺序、分流策略与扣费。

展开看详细说明（新手向）

这个功能解决什么？你从多家上游买了同一个模型（比如两家都有 gpt-4o），不汇总的话前台会出现两条一样的模型，用户不知道选哪个，还容易挑到不稳定的那家。汇总后前台只有一条 gpt-4o，背后两家自动轮流或互为备份。

两种分流策略：

  • 故障自动转移（默认）：永远先用列表里第一个渠道，它在连接失败 / 限流 / 5xx / 密钥失效时自动换下一个渠道重试，用户无感。
  • 轮询：每次请求按顺序换一个渠道，把调用量摊到各家（适合按量套餐或多账号均衡负载）。

顺序就是优先级：列表顺序＝前台显示顺序，也是「故障自动转移」的尝试顺序。用上/下按钮调整。

失败重试只在「还没开始回答」时发生：一旦上游已经吐出第一个字并开始回给用户，就不会再换渠道（否则会出现两段拼接的回答），此时按正常失败处理。

扣费怎么算？留空时按「候选里最贵的一个」预扣，上游返回后按实际命中的那个渠道结算、多退少补。若组内多个渠道单价不同，建议直接在这里填一个固定次数。

窗口与输出上限：取候选里最小的那个，保证同一个请求对任何一个渠道都塞得下。

权限：汇总项会按每个用户自己的「模型授权」过滤 —— 用户无权访问的渠道不会进入候选，也不会被故障转移用到。

故障渠道自动跳过：某个渠道近期连续失败会被熔断，请求直接落到还活着的渠道。

性能优化

用于降低前台首屏加载体积，适合带宽受限、访客网络较慢或主要用纯文本对话的场景。默认全部关闭。开启后，相关资源在前台不再加载，对应能力会退化为纯文本显示（数学公式、图表、代码高亮会以源码形式呈现）。改动在用户下次访问时生效。

说明：开启「内置字体默认不加载」后，前台默认使用系统字体（Apple/微软雅黑/PingFang 等），加载更快；用户仍可在「设置 → 外观」里自行切换为思源宋体等内置字体（切换后会按需加载该字体）。关闭该选项则恢复默认使用内置字体。

在线浏览器

用户在对话侧栏「在线浏览器」中输入网址或直接搜索：网页由本站服务器抓取、改写后在同源下渲染，因此目标网站看到的是本机的出口 IP 而不是用户的 IP；页面跑在 sandbox 隔离的框里，读不到本站登录令牌。网页顶部可一键「AI 总结」，走与对话相同的计费通道。

开启后，代理出网只会走向解析在境内（中国大陆）IP 段的站点，境外站点与域名会直接拒绝并给出提示。判定用的是随包发布的境内 IP 段表（lib/cn-ip.bin，约 1.1 万个网段），只在服务端做，不请求任何外部接口。「放行海外静态资源」解决「百度等国内站打不开」：国内大站的图片/脚本常挂在海外 CDN 上（实测百度首页会引用 ir.baidu.com，它解析到 Akamai），逐个域名判归属会把首页打残；开启后只对「已被某个境内页面引用过」的资源主机放行，且网页本身（HTML 文档）仍必须解析在境内。「域名白名单」解决「按 IP 判会误拦」：有些站点的解析结果就在境外 IP 上（国内站用海外 CDN/DNS，境外学术站本身如此），这些域名不看 IP 直接放行；填一级域名即放行其全部子域名。关掉即恢复为可访问任意公网站点——出口 IP 的声誉与流量都算在本站账上，请自行评估风险。

提醒：若目标站对数据中心 IP 有风控（如某些搜索引擎常返回验证码），属于预期现象，可在「平台配置 → 联网搜索」里配置外部检索源作为替代。

在线工具箱

用户在对话侧栏「在线工具箱」（在「在线浏览器」下方）里存放自写的 HTML 单页，之后一键打开运行：像一个只属于他自己的小工具箱。工具内容按用户隔离，存在数据库里、跟着账号走，换设备登录也能看到。

安全说明（请勿绕过）：工具里的 HTML 由用户自己写，服务端不做任何清洗——脚本、表单、内联样式都是这类小工具的正当用法。隔离靠的是不透明源沙箱：面板内预览用 iframe sandbox（不带 allow-same-origin），「在新标签页打开」时响应头再带一层 CSP sandbox。两条路都让工具读不到本站的登录令牌，也无法通过弹窗挣脱沙箱。因此：不要为了让某个工具「能调本站接口」而去掉沙箱或改成同源直出——那等于把账号交给任意一份粘贴进来的 HTML。

每个用户最多 50 个工具，单个工具 HTML 上限 200000 字符，合计上限 4000000 字符；超出时会明确报错而不是截断。工具在沙箱里运行，不能调用本站接口、也访问不到站内数据。

系统工具（全员共用）

这里维护的工具会出现在前台工具箱的「系统工具」区，所有能用工具箱的人都能直接打开运行，也可以把它们「加入我的工具箱」再改成自己的。出厂预置了 10 套常用小工具（Base64 编解码、URL 编解码、JSON 格式化、时间戳转换、哈希计算、正则测试、随机密码、UUID、颜色转换、文本处理），可以在这里改标题、换内容或删掉。分类只影响分组显示，删掉分类不会删除里面的工具。

这些 HTML 与用户自存的工具同等待遇：服务端不做任何清洗，打开时一律运行在不透明源沙箱里（面板内 iframe sandbox、新标签页响应头 CSP sandbox），因此工具读不到本站登录令牌。演示账号不能修改系统工具——它不在演示还原范围内，放行等于允许演示者永久删掉全站内置工具。

注册与账号安全

关闭后登录页不再显示注册入口，注册接口也会直接拒绝（已有账号可正常登录）。

账号注销

用户在「设置 → 账户」可自助注销。软注销会清除其资料、对话与自建供应商，并把用户名改为「原名-已注销-随机码」、邮箱加 deleted+ 前缀 —— 因此原用户名与原邮箱都可被重新注册；账号记录保留，便于后台追溯。硬注销则直接删除账号及其全部数据，不可恢复。

游客体验

开启后，未登录访客访问首页即可直接对话。每位访客会自动创建一个独立游客账号（命名如「游客A1B2C」并归入「游客」用户组），便于在「用户」列表里单独管理与清理。游客额度在「模型授权」中按游客组控制，轮数在下方设置。

会话有效期修改后对新登录生效；「强制全站下线」会使所有人的现有登录态立即失效（包括你自己），需要重新登录。

添加固定兑换码

自定义码面（如 WELCOME2026），适合做活动通用码。可设置总兑换次数与每次兑换获得的额度；开启「每个用户限兑一次」后同一账号只能使用一次。

联网搜索

开启后，对话会先检索网页再作答，回复底部附来源链接。

Tavily 需在 tavily.com 申请 Key（免费 1000 次/月）。Brave 在 brave.com/search/api 申请（免费 2000 次/月）。DuckDuckGo 与 Jina 免 Key（DuckDuckGo 抓结果页，有速率限制；Jina 免登录额度有限，填 Key 更稳）。SearXNG 每行一个实例根地址，需开启 JSON 格式（format=json）；对话检索按顺序尝试，当前实例失败或没有结果时自动换下一个。探测会拉取 searx.space 使用的官方公共目录（约 80 个 HTTPS 实例）并分批测试，可用的排在前面，点「填入」会追加到列表。

文档解析

支持 PDF、图片、Word、PPT、Excel、HTML。可按文件类型分别指定解析通道；解析不扣对话次数。

通道说明：MinerU 全格式（PDF/图片/Office/HTML）；PaddleOCR 仅 PDF 与图片（自建 PaddleX serving 或 AI Studio API）；Mistral OCR 支持 PDF/图片/DOCX/PPTX。路由到某通道但未配置时，该类文件解析会报错提示。

当前：轻量解析。单文件不超过 10MB、20 页，同一 IP 每分钟有次数限制。用户上传后直接解析，只有超限或失败时才会看到限制。
